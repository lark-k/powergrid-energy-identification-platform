# 分钟级实时光伏功率分离

完整的功率组成关系为：

```text
总开功率 = 光伏功率 + 能源站功率 + 充电桩功率 + 其他负荷功率
```

当前光伏分离数据只包含同步的总开、光伏和能源站表。充电桩馈线最早从 2025-12-22 18:12 开始，而同步总开/光伏/能源站数据最晚到 2025-12-12 09:34，时间重叠为 0 分钟。因此当前模型没有用充电桩分量训练，也没有验证充电桩运行时的光伏分离精度。

## 最终模型

最终选择 `causal_tcn_lstm`。这是同一时刻的功率分离模型：分钟 `t` 已经到达后，模型使用 `t-239` 至 `t` 的总开数据，估计总开在分钟 `t` 中包含的光伏发电功率。它不输出 `t+1` 或更远时刻的功率，不属于光伏功率预测或天气预报任务。

输入特征：

- 总有功功率；
- A/B/C 三相有功功率；
- 总有功功率一分钟变化量；
- 分钟时刻的正弦、余弦编码。

输出：

- 光伏运行概率；
- 正值形式的当前分钟光伏分量`分离光伏发电功率(kW)`；
- 与原始光伏表一致的当前分钟负功率分量`分离光伏有功功率(kW)`。

推理 CSV 使用中文表头，只输出正式的光伏分离字段，不再包含重复兼容列。

模型使用共享的因果 TCN 提取局部及长时间模式，再由单向 LSTM 汇总历史状态。训练采用光伏启停 BCE 与加权 Huber 功率回归的多任务损失。

## 数据划分

训练数据：

- `202511050004 总开`
- `202511050001 光伏`
- `202511250005 能源站`

后期验证和测试数据：

- `台区数据总开0`
- `台区数据光伏0`
- `台区数据能源站0`

后期数据的前 40% 用作验证，中间 20% 作为隔离缓冲，最后 40% 作为独立测试，避免相邻滑动窗口泄漏。

分钟下采样质量使用 `coverage_ratio` 检查。原本缺行、功率无效或覆盖率低于 0.1 的分钟统一视为缺失；若缺口两端都有真实分钟且连续不超过 3 分钟，则按时间做双侧线性插值，不做前向填充。覆盖率在 0.1 至 0.999 的分钟保留已有样本均值，因为直接按 `is_complete=1` 全删会使长连续窗口几乎全部消失。

第二批同步数据中，总开/光伏/能源站分别插值 1/10/11 个源分钟，均为单分钟缺口且全部有双侧锚点。插值分钟保留 `is_interpolated` 标记。240 分钟窗口可以把已经到达的插值分钟作为历史上下文，但目标分钟必须同时具有真实总开和真实光伏读数；因此不会用未来信息估计当前目标，也不会把插值光伏当作测试真值。超过上限、位于首尾或缺少双侧锚点的缺口不填，窗口不能跨越未填缺口。总开一分钟差分在每个连续片段开头重置为 0。

## 模型比较

| 模型 | 参数量 | 验证 MAE | 验证发电时 MAE | 测试 MAE | 测试发电时 MAE |
|---|---:|---:|---:|---:|---:|
| 因果 TCN | 25,610 | 1.078 kW | 2.537 kW | 1.397 kW | 2.544 kW |
| 因果 TCN-LSTM | 34,058 | **0.644 kW** | **1.715 kW** | **0.528 kW** | **1.293 kW** |

最终 TCN-LSTM 独立测试指标：

- MAE：0.528 kW；
- RMSE：1.504 kW；
- R²：0.896；
- 光伏发电时 MAE：1.293 kW；
- 夜间/不发电时误发电 MAE：0.194 kW；
- 测试期真实发电量：189.477 kWh；
- 分离得到的发电量：187.278 kWh；
- 电量偏差：-1.16%；
- 光伏启停 Accuracy：0.9472；
- 光伏启停 F1：0.9192；
- 光伏启停 ROC-AUC：0.9921；
- 光伏启停召回率：0.9723。

整批后期总开数据的端到端分离共输出 12,372 个分钟结果；其中 12,362 个结果能与真实（非插值）同期光伏目标对齐，MAE 为 0.646 kW，发电时 MAE 为 1.550 kW，累计电量偏差为 -3.73%。其中 239 个窗口的历史部分包含插值分钟，所分离的当前目标分钟均为真实数据。

模型常驻 GPU 时，单个 240 分钟窗口的平均前向计算时间约 2.0 ms，不包含磁盘读取和首次模型加载。

## 使用

批量处理一个总开分片文件夹：

```powershell
python predict_pv_disaggregation.py "..\台区数据总开0" `
  --output ".\pv_outputs\predictions.csv"
```

只分离最新已到达分钟：

```powershell
python predict_pv_disaggregation.py "..\台区数据总开0" --latest-only
```

实时系统应常驻加载模型，维护最近 240 分钟的环形缓冲区，每收到一个新分钟数据执行一次推理。若最新分钟缺失或质量不合格，`--latest-only` 会等待下一分钟形成双侧锚点后再输出，不会前向填充最新值。直接每分钟重新启动脚本会把 Python、模型和 CSV 加载时间也计入延迟。输出中的`窗口内插值分钟数`可用于审计历史窗口中的插值数量。

## 使用边界

当前模型只使用一个项目、约两批日期的数据。它能学习该台区能源站和光伏的联合运行规律，但在其他容量、季节、天气或控制策略下不保证保持同样精度。

当光伏、能源站、充电桩或其他负荷同时变化时，仅凭总开功率无法形成数学上唯一的分解；模型输出是基于历史模式的估计。当前测试结果不能外推为“已验证可抵抗充电桩干扰”。

如果实时能源站表和充电桩表可用，应将两者作为输入，或采用“总开减能源站减充电桩＋残差模型”。若只允许总开作为在线输入，则训练阶段仍需要同一计量边界、同一分钟的总开/光伏/能源站/充电桩数据，才能正确学习并验证充电桩干扰。
