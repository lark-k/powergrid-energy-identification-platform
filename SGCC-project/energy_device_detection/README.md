# 总开资源实时辨识与光伏实时分离

本目录交付两套已经训练完成、相互独立的分钟级模型：

1. 三类资源实时辨识：从总开/馈线功率输出当前分钟的`光伏运行状态`、`能源站运行状态`和`充电桩运行状态`；
2. 光伏实时分离：从总开功率输出当前分钟的`分离光伏发电功率(kW)`。

两者都只处理已经到达的当前分钟，不读取 `t+1`，也不预测未来。辨识输出表示当前是否存在可辨识的运行信号，并不等同于设备是否物理安装；光伏分离输出是总开中当前分钟的光伏功率分量。光伏分离的详细设计和测试结果见 [`PV_DISAGGREGATION.md`](PV_DISAGGREGATION.md)。

各文件职责、CSV输入格式、推理命令和完整训练流程见 [`README_USAGE.md`](README_USAGE.md)。

## 最终模型与精度

| 任务 | 最终模型 | 测试结果 |
|---|---|---|
| 三类资源实时辨识 | 末端因果 TCN-LSTM，输入最近 120 分钟 | Macro F1 **0.9145**，Macro ROC-AUC **0.9778**，Hamming Accuracy **0.9578** |
| 光伏实时分离 | 因果 TCN-LSTM，输入最近 240 分钟 | MAE **0.528 kW**，RMSE **1.504 kW**，R² **0.8962**，累计电量偏差 **-1.16%** |

辨识的分类指标和分离的连续功率误差不是同一种准确率。由于充电桩与总开/光伏/能源站批次没有同步时间重叠，不能把充电桩结果表述为已经在真实四类混合总开中验证。

## 结论

当前模型是因果的实时多标签辨识：分钟 `t` 到达后，只使用 `t-119` 至 `t` 的总开功率，输出当前分钟 `t` 的三类资源运行状态，不读取或预测 `t+1`。工作区原有文件只有网络骨架：

- `model.py` 使用了与当前目录不一致的 `from TCN.tcn` 导入路径；
- 输出只是 `embedding_dim` 向量，没有明确的三标签分类定义；
- 没有数据对齐、训练/验证划分、损失函数、阈值校准和评估；
- 原有窗口累计标签不能表示当前状态，可能产生约12分钟确认延迟。

同一数据划分的实测结果如下：

| 模型 | 参数量 | 验证集 Macro F1 | 后期测试集 Macro F1 | 测试集完整匹配率 |
|---|---:|---:|---:|---:|
| 末端因果 TCN | 19,547 | 0.9641 | 0.9029 | 0.7000 |
| 末端因果 TCN-LSTM | 27,995 | **0.9700** | **0.9145** | **0.7083** |

因此最终选择末端因果 TCN-LSTM。选型只使用验证集；测试集没有参与模型选择。

“完整匹配率”只在三个标签都有监督的 1,200 个合成测试窗口上计算；单标签指标则使用该标签有真实或合成监督的全部窗口。

选中模型在测试集上的分类结果：

| 标签 | Precision | Recall | F1 | ROC-AUC | Specificity |
|---|---:|---:|---:|---:|---:|
| 光伏 | 0.8112 | 0.9500 | 0.8751 | 0.9640 | 0.8860 |
| 能源站 | 0.8861 | 0.8618 | 0.8738 | 0.9694 | 0.9629 |
| 充电桩 | 0.9909 | 0.9985 | 0.9947 | 0.9999 | 0.9924 |

光伏是当前最弱的标签，主要因为光伏负功率会被能源站和其他负荷叠加抵消；后续最值得补充的是更多季节、天气和不同台区的同步总开/光伏数据。

实时可行性验证通过：默认每分钟产生一次当前状态，`--latest-only` 只返回最新已到达分钟；单窗口 GPU 前向计算约 1.20 ms。详细结果见 `artifacts/realtime_identification_evaluation.json`。

## 数据如何整合

### 光伏与能源站

按 `minute_start` 对齐以下两批同步数据：

- 训练批次：`202511050004 总开` + `202511050001 光伏` + `202511250005 能源站`
- 验证/测试批次：`台区数据总开0` + `台区数据光伏0` + `台区数据能源站0`

第一批共 11,705 个对齐分钟。总开减去光伏和能源站后的残差标准差约 0.304 kW，说明三个表的同步关系可靠。

### 充电桩

- 较早批次：`台区数据12号`、`台区数据13号`
- 较晚批次：`充电桩台区2.1-20251231-20260109-12号`、`充电桩台区2.2-20251231-20260109-13号`

`充电桩台区1_12.22-12.31_12号` 的 476 行与 `台区数据12号` 同期数据几乎完全相同，属于重复采集片段，不作为独立监督标签使用。

`台区数据12号/13号` 没有因为目录名未注明用途就被随意归类：两者都呈现低功率待机与固定高功率平台切换，并且处理日志中的归档文件名与后来明确标注的 12/13 号充电桩目录同源。训练前还会按功率分位数、日夜形态和启停平台自动校验全部目录的角色；形态与预期不一致时停止构建。审计结果见 `artifacts/data_inspection.json` 和两个数据集 metadata 中的 `role_audit`。

充电桩数据从 2025-12-22 18:12 开始；同步总开/光伏/能源站数据在 2025-12-12 09:34 结束，两者时间重叠为 0 分钟。所以下述三类资源组合来自合成混合，不是同一时刻、同一总开计量边界下的真实组合。

### 样本定义

- 输入窗口：连续 120 分钟；
- 训练和推理步长：1 分钟；
- 输入通道：总有功功率、A/B/C 三相有功功率；
- 光伏分钟标签：光伏功率 `<= -0.5 kW`；
- 能源站分钟标签：能源站馈线功率 `>= 5.0 kW`；
- 充电桩分钟标签：充电馈线功率 `>= 1.0 kW`；
- 输出标签：窗口末端当前分钟的三类运行状态；前119分钟只作为历史上下文。

同步总开窗口没有充电桩表，因此其充电桩标签设为未知；充电馈线窗口没有同步光伏/能源站表，因此这两个标签也设为未知。未知标签通过 `label_mask` 从损失、阈值校准和指标中排除，不再错误地当成 0。

训练集还加入了残余基础负荷、光伏、能源站、充电桩的合成混合，覆盖真实观测中缺少的多设备组合。这是非同期分量相加得到的数据增强，不是真实同步观测。较早批次用于训练，较晚批次被分成验证和测试段，中间留有时间缓冲，避免相邻窗口泄漏。

分钟数据按 `coverage_ratio` 做质量控制。原本缺行、功率无效或覆盖率低于 0.1 的分钟统一视为缺失；若缺口两端都有真实分钟且连续不超过 3 分钟，则按时间做双侧线性插值。覆盖率在 0.1 至 0.999 的分钟保留其已有样本均值；没有按 `is_complete=1` 全删，因为那会使当前数据中的长连续窗口几乎全部消失。插值分钟保留 `is_interpolated` 标记，当前辨识分钟必须有真实总开读数；对应资源分表的当前分钟若为插值值，该标签通过 `label_mask` 从监督和评估中排除。超过上限、位于首尾或没有双侧锚点的缺口不填，窗口不能跨越未填缺口。

当前实际参与建模的数据共插值 285 个源分钟：第二批总开/光伏/能源站分别为 1/10/11 分钟，较早两路充电馈线分别为 215/48 分钟，较晚两路为 0。所有这些缺口都不超过 3 分钟并已填补。

|---|---:|
| 训练 | 42,007 |
| 验证 | 16,457 |

## 主要文件

- `data_pipeline.py`：读取分片 CSV、时间对齐、构造真实和合成窗口；
- `models.py`：TCN 与修复后的 TCN-LSTM；
- `train.py`：训练、阈值校准、模型对比和选型；
- `predict.py`：对新总开 CSV 或分片文件夹执行推理；
- `artifacts/device_detection_dataset.npz`：已整合训练数据；
- `artifacts/dataset_metadata.json`：数据划分、阈值和归一化信息；
- `outputs/model_comparison.json`：完整验证/测试指标；
- `artifacts/realtime_identification_evaluation.json`：实时语义、精度、响应延迟和计算延迟评估；
- `artifacts/model_contracts.json`：资源辨识与光伏分离两套模型的正式输入输出契约；
- `outputs/selected_model.pt`：最终选中的实时 TCN-LSTM 模型；
- `outputs/realtime_identification_main_b.csv`、`outputs/realtime_identification_charger_12.csv`：逐分钟端到端辨识示例；
- `outputs/latest_identification_main_b.csv`：最新分钟辨识示例。

## 重新运行

```powershell
python data_pipeline.py
python train.py --epochs 20 --patience 5 --batch-size 1024 --learning-rate 0.002
python predict.py "..\台区数据总开0" --output ".\outputs\predictions.csv"
python predict.py "..\台区数据总开0" --latest-only
```

运行环境需要 NumPy、pandas、PyTorch；本次实测使用 PyTorch 2.6.0 和 CUDA。

推理 CSV 使用中文表头，并包含`窗口内插值分钟数`，便于审计窗口中使用了多少个插值历史分钟。

## 使用边界

当前模型辨识的是当前分钟是否出现可辨识的设备运行信号，不是在设备全程休眠时证明其物理上已经安装。尤其是夜间完全不发电的光伏，单凭总开功率无法可靠证明存在。

充电桩标签来自充电台区总馈线的功率阈值，而不是独立的桩端子表；充电桩与同步总开/光伏/能源站批次也没有时间重叠。因此充电桩指标是“充电馈线实测窗口＋非同期分量合成组合”上的工程基线，不能视为已经在真实同步总开混合场景中验证。新增同一计量边界的同步总开/光伏/能源站/充电桩数据后应重新训练和测试。当前数据也主要来自同一项目和有限日期，在部署到其他台区之前需要用其他台区做外部测试。
