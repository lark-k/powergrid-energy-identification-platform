# 台区能源辨识与光伏功率分离平台接口文档

> 版本：V1.1  
> 更新日期：2026-07-28  
> 接口前缀：`/api/v1`  
> 对应前端模型：`frontend/src/types/domain.ts`

## 1. 快速说明

平台包含三类数据接口：

1. **首页大屏**：快照、历史记录、导入和导出。
2. **数据采集过程页**：采集源、处理步骤、质量状态、实时事件和信号。
3. **模型训练过程页**：训练步骤、epoch 指标、验证结果和版本发布检查。

推荐接入顺序：

```text
首页快照
  ↓
采集过程 REST + SSE
  ↓
训练运行记录
  ↓
历史查询、导入、导出
```

## 2. 通用约定

### 2.1 时间

所有时间使用带时区的 ISO 8601：

```text
2026-07-28T18:37:00+08:00
```

关键时间含义：

| 字段 | 含义 |
| --- | --- |
| `event_time` | 数据实际产生的业务时间 |
| `arrival_time` | 数据到达平台的时间 |
| `separation_time` | 模型完成推理的时间 |
| `updated_at` | 数据或状态最近更新时间 |

反馈必须根据历史 `event_time` 匹配，不能使用 `arrival_time` 代替业务时间。

### 2.2 数值

| 字段 | 约定 |
| --- | --- |
| `*_kw` | kW |
| `*_kvar` | kvar |
| `*_ms` | 毫秒 |
| `score`、`confidence`、`*_ratio` | 0～1 小数 |

例如完整率 96.8% 应返回 `0.968`。

### 2.3 空值

反馈尚未到达时，以下字段返回 `null`，不能用 `0` 代替：

- `corrected_pv_kw`
- `station_feedback_value`
- `correction_kw`
- `correction_ratio`
- `batch_id`

### 2.4 HTTP

- JSON 编码：UTF-8。
- 成功查询：`200 OK`。
- 创建成功：`201 Created`。
- 异步任务：`202 Accepted`。
- 快照和过程接口直接返回业务对象，不额外包裹 `data`。

### 2.5 列表分页

历史列表统一支持：

| 参数 | 说明 |
| --- | --- |
| `from` | 开始时间，包含 |
| `to` | 结束时间，不包含 |
| `cursor` | 上一页返回的游标 |
| `page_size` | 默认 500，最大 5000 |
| `order` | `asc` 或 `desc` |

列表响应：

```json
{
  "items": [],
  "next_cursor": null,
  "has_more": false
}
```

### 5.2 订阅采集过程

```http
GET /stations/{station_id}/process/collection/stream
Accept: text/event-stream
```

用途：过程页打开后持续更新状态。

服务端事件：

```text
id: EVT-COL-20260728-183705
event: telemetry
data: {"source":"sse","process_id":"COL-A01",...}
```

`data` 的 JSON 结构与 5.1 完全相同，仅 `source` 改为 `sse`。

建议：

- 每 3～5 秒推送一次，或状态变化时推送。
- 每 20～30 秒发送 SSE 注释心跳：`: heartbeat`。
- 客户端断线重连后，先调用 REST 接口恢复完整状态。
- `id` 应唯一，便于使用 `Last-Event-ID` 续传。

## 7. 首页核心对象

### 7.1 总开分钟数据

```json
{
  "station_id": "A01",
  "event_time": "2026-07-28T18:37:00+08:00",
  "active_power_kw": 24662,
  "reactive_power_kvar": 4439,
  "voltage": 231.6,
  "current": 64899.2,
  "pf": 0.971,
  "quality_flag": "good"
}
```

### 7.2 分钟分离结果

```json
{
  "event_time": "2026-07-28T18:37:00+08:00",
  "separation_time": "2026-07-28T18:37:02+08:00",
  "result_status": "等待反馈",
  "total_power_kw": 24662,
  "initial_pv_kw": 660,
  "pv_activity_probability": 0.872,
  "interpolated_minutes": 0,
  "corrected_pv_kw": null,
  "station_feedback_value": null,
  "feedback_status": "等待回传",
  "correction_kw": null,
  "correction_ratio": null,
  "confidence": 0.872,
  "model_version": "PV-Sep v3.2.7",
  "batch_id": null,
  "participating_nodes": [],
  "model_window_start": "2026-07-28T17:37:00+08:00",
  "model_window_end": "2026-07-28T18:37:00+08:00",
  "remaining_load_kw": 25322
}
```

计算约定：

```text
correction_kw = initial_pv_kw - corrected_pv_kw

有反馈：
remaining_load_kw = total_power_kw + corrected_pv_kw

无反馈：
remaining_load_kw = total_power_kw + initial_pv_kw
```

其中 `total_power_kw` 保留总开净交换功率的正负号，光伏分离结果使用正的发电功率幅值，
因此估算本地负荷需要将两者相加。`pv_activity_probability` 仅表示光伏活动概率，
不是功率回归准确度；`interpolated_minutes > 0` 时应结合 `quality_status` 显示输入质量告警。

### 7.3 辨识结果

```json
{
  "result_time": "2026-07-28T18:36:56+08:00",
  "window_start": "2026-07-28T12:37:00+08:00",
  "window_end": "2026-07-28T18:37:00+08:00",
  "model_version": "LGR-Multi v2.4.1",
  "items": [
    {
      "kind": "pv",
      "label": "存在",
      "score": 0.972,
      "features": ["日照相关性", "午间反向特征"]
```

`pv`、`energy_station`、`charger` 是三个独立标签，不是互斥分类。当前仅展示能源站和充电桩的辨识分数，不返回伪造的分离功率。

## 9. 首页实时推送

首页可继续使用 WebSocket：

```text
WS /api/v1/stream?stationId=A01
```

MVP 可以推送完整快照：

```json
{
  "type": "snapshot.updated",
  "event_id": "EVT-20260728-183700-001",
  "emitted_at": "2026-07-28T18:37:03+08:00",
  "station_id": "A01",
  "data": {}

```

`data` 与第 4 节快照结构相同。

数据量增大后可改为增量事件：

| `type` | 触发时机 |
| --- | --- |
| `minute.created` | 新分钟推理完成 |
| `recognition.updated` | 新辨识结果产生 |
| `feedback.arrived` | 反馈批次到达并完成校正 |
| `training.updated` | 训练摘要变化 |
| `node.status.updated` | 节点状态变化 |
| `quality.updated` | 质量汇总变化 |

## 11. 错误响应

统一结构：

```json
{
  "code": "STATION_NOT_FOUND",
  "message": "台区 A01 不存在",
  "request_id": "REQ-20260728-001",
  "details": {}
}
```

常用错误：

| HTTP | `code` | 说明 |
| --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | 参数错误 |
| 401 | `UNAUTHORIZED` | 未登录或令牌失效 |
| 403 | `FORBIDDEN` | 无访问权限 |
| 404 | `STATION_NOT_FOUND` | 台区不存在 |
| 422 | `DATA_VALIDATION_FAILED` | 数据校验失败 |
| 500 | `INTERNAL_ERROR` | 后台内部错误 |
| 503 | `MODEL_SERVICE_UNAVAILABLE` | 模型服务不可用 |

## 12. 关键业务规则

1. 反馈仅在 `arrival_time <= 当前查询时刻` 时可见。
2. 反馈按覆盖区间匹配历史 `event_time`。
3. 反馈到达分钟不能被错误当作反馈覆盖分钟。
4. 每条辨识和分离结果必须保存 `model_version`。
5. 训练过程数据必须来自实际运行记录。
6. 比例返回 0～1；无数据返回 `null`。
