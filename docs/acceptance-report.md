# 实施验收报告

日期：2026-08-02

## 本轮优化结果

- 新增历史数据范围接口和前端“实时/历史截止”切换，历史查询以数据库 `event_time` 为准，不再要求样例时间接近电脑当前时间。
- 新增持久化历史推理回放任务。Java 从数据库读取总开分钟窗口，批量调用 Python `/internal/v1/inference/replay`，幂等保存辨识与光伏分离结果。
- 总开曲线和总开指标直接使用原始分钟数据；光伏曲线只使用真实分离结果。模型无输出时保留 `null`，不会伪造 0。
- 历史快照严格使用查询截止时间，不泄漏未来辨识、反馈或校正；反馈仍按 `arrival_time` 可见、按 `event_time` 匹配。
- 后端重启后从数据库恢复最近真实模型版本展示，同时以 Python readiness 判断当前模型是否可用。
- Java/Python 回放契约、OpenAPI、Flyway V2、前端适配器和回归测试已同步更新。
- 新增受控 SGCC 总开历史导入器：默认仅校验，显式 `--apply` 后才写库；支持批量幂等新增、修复已有分钟以及关闭导入期逐分钟推理。
- 修复 Java 对 `phase_a_power_kw`、`phase_b_power_kw`、`phase_c_power_kw` 的显式 JSON 字段映射。旧样例曾将三相功率静默读为 0，现已由 SGCC 原始数据修复并通过数据库抽样核对。

## 当前明确边界

- 当前仅对光伏进行数值功率分离；能源站和充电桩只输出辨识概率与状态。
- 当前充电桩数据尚未与其他资源完成真实同步混合验证。
- 当前模型在其他台区正式应用前需要外部测试和人工验收。
- 系统仅提供只读监测分析，不提供设备控制、调度指令或自动闭环。
- 无真实 `training_epoch`、反馈或模型输出时，接口和页面保持为空，不生成演示值。
- 当前没有创建光伏分站反馈批次，因此 `corrected_pv_kw`、`correction_kw` 和 `batch_id` 均保持 `null`；不得把 SGCC 文件中的其他资源数据或模型初始分离值冒充反馈校正。
